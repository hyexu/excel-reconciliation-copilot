# Excel Reconciliation Copilot

**재무·회계 실무형 포트폴리오 | 장부 ↔ 은행 거래 자동 대사**

두 개의 엑셀을 업로드해 거래별 매칭을 수행하고, 미대사·수수료 추정·기표일 시차·분할/합산 거래·중복 의심을 구분하는 Streamlit 웹앱입니다.

## 주요 기능

- **정확 일치:** 거래처·거래일자·금액 동일
- **날짜 시차:** 거래처·금액 동일, 설정한 날짜 오차 이내
- **수수료 추정:** 거래처 동일, 설정한 소액 차이 이내. **확정 분개가 아님**
- **1:N / N:1:** 동일 거래처·부호·기간 내 부분 거래의 합계가 정확히 일치
- **중복 의심:** 동일 날짜·거래처·금액의 반복 거래 별도 표시
- **미대사:** 장부/은행 각각 미매칭 거래, 관련 후보 및 검토 의견
- **다운로드:** 요약·대사결과·미대사·중복의심 시트 포함 XLSX

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 `samples/ledger_sample.xlsx`와 `samples/bank_sample.xlsx`를 업로드합니다.

## 테스트

```bash
python -m pytest -q
```

## 입력 파일 규칙

첫 번째 시트에 `거래ID`, `거래일자`, `거래처`, `금액` 열이 필요합니다. ID는 파일 내에서 고유해야 하며 날짜는 Excel 날짜 또는 `YYYY-MM-DD` 형식, 금액은 원 단위 정수입니다. **입금은 양수, 출금은 음수로 양쪽 파일을 동일하게 입력**합니다. 실제 데이터는 로컬/브라우저 세션에서 처리되며 이 앱은 외부 LLM API를 호출하지 않습니다. 공개 서버에 민감한 실거래 자료를 업로드하지 마세요.

## 매칭 우선순위와 내부통제

1. 고유한 정확 일치 → 2. 고유한 날짜 시차 → 3. 고유한 수수료 추정 → 4. 모호하지 않은 분할/합산.

여러 거래가 같은 조건에 해당하면 **임의로 하나를 선택하지 않고 미대사로 보류**합니다. 중복 의심은 별도 플래그이며 정상 반복 결제일 수 있습니다. 1:N 매칭은 조합 수 제한(최대 4건)을 두어 계산량을 관리합니다. 동일 거래처 표기는 공백·대소문자만 정규화하며 별칭 매핑은 제공하지 않습니다. 거래 방향이 반대면 매칭하지 않습니다.

### 회계적 검토 포인트

- **시차:** 미결제, 미입금, 결산일 전후 cut-off 여부 확인
- **수수료:** 은행 수수료·정산 공제 등 증빙 확인 후 별도 회계처리
- **분할/합산:** 정산서, 송금증빙과 실제 구성 거래 검증
- **미대사:** 누락 기표, 미결제 거래, 은행만 반영된 항목 확인
- **중복:** 정상 정기 결제와 이중 기표를 구별

## 한계

금액·거래처 기반의 규칙 엔진이며 AI/ML 판단을 하지 않습니다. 수수료 추정 매칭은 실제 회계처리의 확정이 아니며, 여러 건의 수수료가 포함된 N:M 매칭, 거래처 별칭, 환율차이, 원천징수, 취소/환불 연계는 현재 범위 밖입니다. 장부 매칭률은 **장부 행 기준**이며 분할 거래는 각 행을 별도로 셉니다. 총액 차이는 매칭된 차이까지 포함한 원장 전체 합계의 차이입니다.

## 포트폴리오 요약

> 반복적인 장부·은행 거래 대사 업무를 Python과 Streamlit으로 자동화했습니다. 매칭 정확도뿐 아니라 회계상 시차, 수수료, 분할 입금 및 중복 기표 가능성을 별도 검토 항목으로 분리하고, 모호한 거래는 자동 확정하지 않는 통제 설계를 적용했습니다.
